## 워크플로우

### 1. 트래커 초기화/갱신

`_workspace/submission/submission_tracker.md`가 단일 진원지다. 없으면 아래 구조로 생성, 있으면 상태 diff만 갱신한다.

```markdown
# 제출 추적 (갱신: YYYY-MM-DD)

## 1차 제출 패키지
| 항목 | 상태 | 마감 | 액션 주체 | 비고 |
|------|------|------|----------|------|
| 제출 양식 작성 | 미착수/진행/완료 | 09-21 | 사용자+에이전트 | |
| 서비스 URL (프로덕션) | | 09-21 | 에이전트 검증 | |
| 활용 API 명세 (14종) | | 09-21 | 에이전트 | 미사용 2종 사유 포함 |
| 운영계정 인증키 | | 1차 심사 전 | **사용자 액션 필요** | MobileApp=GreenTrip |
| 위치기반 사업자 등록 | | 1차 심사 전 | **사용자 액션 필요** | legal 트래커 연동 |
```

상태 정의: 완료 = 외부에서 검증 가능한 증거(승인 메일, 발급된 키, 등록증)가 있는 상태. "신청서 보냄"은 진행이지 완료가 아니다.

### 2. 활용 API 명세 작성

제출 패키지의 핵심. 다음을 정확히 기재:
- **KorService2 활성 13종** + **두루누비 1종** = 14종 (19종 중 약 74%)
- **미사용 2종**(areaCode2·categoryCode2): "신청됐으나 호출 0건 — ldongCode2·lclsSystmCode2로 사전 마이그레이션(2026년 내 폐기 예정 대응)" 사유 명기. 이는 감점이 아니라 데이터 정책 이해도의 증거로 서술한다.
- 작성 전 qa-reviewer에게 14종 실호출 검증을 의뢰하고 결과를 인용한다. **문서 주장과 grep 결과가 다르면 제출 불가** — 두루누비 실호출 여부를 반드시 확인.

### 3. 프로덕션 배포 점검

심사위원이 보는 것은 프로덕션이다. `_workspace/submission/deploy_checklist.md`에 결과 기록:

1. **환경변수** — .env.example의 모든 키가 Vercel에 설정됐는지 (값 자체는 기록 금지, 설정 여부만)
2. **cron** — `/api/tour/sync`가 CRON_SECRET으로 실제 동작하는지 (Vercel cron 로그 확인 절차 안내)
3. **rate limit** — 심사 기간 트래픽에 과도하게 보수적이지 않은지
4. **PWA** — 실 디바이스 설치 프롬프트 (PNG 아이콘 포함 확인)
5. **Lighthouse** — 프로덕션 URL 기준 90+ (로컬 측정값은 무효)
6. **시드 데이터** — 빈 DB로 심사위원이 접속해도 explore·테마 코스가 채워져 있는지

실패 항목은 담당 에이전트(architect/tourapi-integrator/ui-builder)에 파일:라인과 함께 이관하고 트래커에 이관 기록을 남긴다.

### 4. 강원 RTO 특별상 트랙

`_workspace/submission/gangwon_rto_tracker.md`로 별도 관리 (본상과 독립 심사·이중 수상 가능):
- 강원관광재단 접촉 이력, 제안 문구(product-strategist에 의뢰), 의향서(LOI) 상태
- 두루누비 데이터(강원 자전거길 242km·둘레길·DMZ)의 제품 연동 상태가 협업 설득의 증거 — tourapi-integrator의 구현 상태와 동기화
- 목표: PT(10-28) 전 의향서 1건

### 5. 사용자 액션 분리

회원가입·서류·날인·결제는 에이전트가 못 한다. 보고 시 다음 형식으로 분리:

```markdown
## 사용자 액션 필요 (N건)
1. [운영계정] TourAPI 포털 > 마이페이지 > 운영계정 전환 신청 — 필요 정보: 서비스 URL, 앱명 "GreenTrip"
   상태 회신 방법: 승인 메일 수신 시 "운영계정 승인됨"이라고 알려주세요.
```

## 작업 원칙

- 제출 요강·양식은 운영사무국 원문(공지/PDF)을 1차 출처로 한다. 원문이 없는 항목은 `[요강 미확인]`으로 표시하고 추측으로 채우지 않는다 — 잘못된 요강 정보는 누락보다 위험하다.
- 모든 날짜는 절대 날짜(YYYY-MM-DD)로 기록한다. "다음 주" 같은 상대 표현은 트래커에서 금지.
- 시크릿(인증키 값, 토큰)은 어떤 산출물에도 기록하지 않는다. "발급됨/미발급" 상태만.
