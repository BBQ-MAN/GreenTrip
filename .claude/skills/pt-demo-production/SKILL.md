# PT & Demo Production — 발표·시연 제작

2차 PT에서 심사위원이 기억할 한 장면을 만들고, 라이브 시연의 실패 확률을 구조적으로 제거한다.

## 워크플로우

### 1. 심사 기준 → 스토리라인 역설계

`_workspace/benchmark/04_judge_mapping.md`를 읽고 평가 영역별 배점을 발표 시간에 비례 배분한다. 기본 골격:

| 순서 | 내용 | 심사 영역 | 비중 |
|------|------|----------|------|
| 1. 훅 | "같은 여행지, 다른 이동방식" + 국제 관광 탄소의 75%가 운송 부문 (UNWTO — E-ledger E1, v1.1 정본 표현 의무) | 기획력(30) | 짧게 |
| 2. 라이브 시연 | 4클릭 플로우 | 완성도(30) | **최대** |
| 3. 데이터 | 14종 활용 + 폐기 API 사전 마이그레이션 + 호출 통계 대시보드 | 데이터 활용(20) | 중간 |
| 4. 발전성 | B2G·로드맵 + 강원 RTO 협업(의향서) | 발전성(20)+특별상 | 중간 |
| 5. 클로징 | 누적 절감 KPI + 한 장면 리프레이즈 | 기억 | 짧게 |

산출: `_workspace/pt/pt_storyline.md` — 슬라이드 단위 아웃라인 + 각 슬라이드의 심사 영역 태그.

**한 장면 원칙**: 3안 비교 카드에서 절감 % 가 드러나는 순간을 발표의 정점으로 고정하고, 그 전후의 모든 연출(말·슬라이드·마우스 이동)을 그 순간을 향해 설계한다.

### 2. 데모 스크립트 (클릭 단위)

검증된 시연 경로 (코드 기준 4클릭, `_workspace/audit_uiux_20260610.md` 참조):

```
클릭 0  랜딩 — 3안 비교 mock + 67% 절감이 첫 스크롤에 보임 (여기서 가치 제안 한 문장)
클릭 1  /plan — 기본값 그대로 (입력 부담 0을 오히려 강조: "지역과 테마만 고르면 끝")
클릭 2  생성 — 3안 카드 등장 (정점: Carbon Scale·절감%·지도 색 구분을 손으로 가리킴)
클릭 3  추천안 선택 → 코스 상세 (타임라인·지도 오버레이)
클릭 4  인증서 — 소나무 환산 + 카카오 공유 (공유성 = 확산 논리로 연결)
```

각 클릭마다 ① 말할 한 문장 ② 화면에서 가리킬 곳 ③ 실패 시 전환 동작을 표로 작성한다. 산출: `_workspace/pt/demo_script.md`.

### 3. 시연 리스크 제거

라이브 시연 실패의 3대 원인은 네트워크·콜드 캐시·빈 데이터다. 리허설 체크리스트(`_workspace/pt/rehearsal_checklist.md`)에 다음을 포함:

1. **캐시 워밍** — 발표 직전 시연 경로를 1회 완주하여 TourAPI 응답을 Redis에 적재하는 절차
2. **시드 보장** — 시연 계정에 사전 생성된 코스·리포트·인증서 존재 확인
3. **오프라인 백업 2중** — ① 전체 플로우 스크린 레코딩(발표 PC 로컬 저장) ② 정점 장면 정적 스크린샷. 네트워크 단절 시 "녹화 화면으로 이어가겠습니다" 전환 문장까지 대본에 포함
4. **실패 경로 사전 차단** — 시연 경로에서 에러 UI(인라인 alert 등)가 노출될 수 있는 분기를 사전 점검, 결함은 ui-builder에 이관
5. **타이머 리허설** — 규정 시간 - 30초 버퍼로 3회 이상. 초과 시 슬라이드가 아니라 말을 줄인다

### 4. Q&A 은행

3축으로 예상 질문을 수집하고, 모든 답변에 출처(Evidence Ledger ID 또는 파일)를 연결한다. 산출: `_workspace/pt/qa_bank.md`.

- **기술**: 탄소 계수 출처(DEVELOPMENT_PLAN §4.1), 2-opt 한계(20개 상한), transit 안의 경로 단순화(정직하게 Phase 2+ 계획으로 답변), 미사용 2종 사유(폐기 예정 선제 대응)
- **사업**: 수익모델, B2G 대시보드, 지역화폐 연계(Phase 5), 빅테크 진입 시 방어 논리
- **데이터**: KorService1→2 마이그레이션 근거(실측 200 확인), 두루누비 활용 범위, 호출 통계의 실제 수치

답변 원칙: 약점 질문(transit 단순화 등)은 숨기지 않고 "현재 한계 + 로드맵 위치"로 답한다. 심사위원은 약점 부재가 아니라 약점 인지를 평가한다.

### 5. 발표 자산

- 슬라이드는 마크다운 아웃라인까지가 이 스킬의 범위. 시각 디자인은 사용자와 외부 도구(Canva/Figma) 협업을 제안하고, 디자인 토큰(`src/styles/tokens.ts`의 #097A50 계열)을 슬라이드에도 일관 적용하도록 가이드를 첨부한다.
- 핵심 수치 카드(누적 절감 kg·소나무 환산·호출 통계)는 발표 직전 프로덕션 실측값으로 갱신하는 절차를 체크리스트에 포함 — 오래된 mock 수치가 화면 실측과 다르면 신뢰도가 무너진다.

## 작업 원칙

- 정량 주장은 Evidence Ledger에 등재된 것만 발표에 사용한다. 미등재 주장이 필요하면 product-strategist에 검증을 의뢰한 뒤 사용 — 심사 Q&A에서 출처를 못 대면 그 주장 하나가 발표 전체의 신뢰를 깎는다.
- 발표 규정(시간·형식·발표자 수) 원문 미확보 시 `[요강 미확인]` + 보수적 기본값(5분·1인)으로 초안을 만들고 사용자 확인을 요청한다.
- 제품 결함을 발견해도 직접 수정하지 않는다 — 담당 에이전트에 파일:라인으로 이관 (역할 경계 유지).
